# Commits, PRs and branch names

> Commit **only when the user asks**. This skill is about how to write it, not when.

The commit summary, the PR title and the branch name share **one prefix**. One
commit (and one PR) holds one kind of change, so the prefix is unambiguous.
Prefixes follow the convention of the user's `pykorail` repo; all text is English.

```
<PREFIX>: <summary>

<body: why>
```

## 1. Look at the diff first

Pick the prefix from the diff, not from memory.

```sh
git status --short
git diff --stat
git diff            # unstaged
git diff --staged   # staged
```

## 2. Pick one prefix

| Prefix | Use for | Example |
|---|---|---|
| `ADD:`  | something new: feature, scene, demo, tool, workflow, test, dependency | `ADD: Release workflow for <game>-v<version> tags` |
| `FIX:`  | a bug: behaviour differed from the intent | `FIX: Corvane boot hang in EEPROM busy wait` |
| `REF:`  | restructuring with **no visible change** (same ROM behaviour, same output) | `REF: Merge per-stage VRAM tables into one plan` |
| `DEL:`  | removal: feature, file, dead code | `DEL: Unused sky tile generator` |
| `DOCS:` | docs only: READMEs, QA sheets, AGENTS.md, agent config | `DOCS: Stage gallery in the Corvane README` |
| `UPT:`  | **version bump** of something already used | `UPT: BlocksDS image to v1.26.0` |

Upper case, colon, one space. Not `Add:` or `ADD :`.

### Edge cases (decide in this order)

1. **Did visible behaviour change?** No → `REF:`. New behaviour → `ADD:`.
   Wrong behaviour corrected → `FIX:`. A `REF:` that changes what a player,
   builder or emulator sees has the wrong prefix.
2. **Hardware or emulator surprises are `FIX:`.** Code that broke on melonDS, a DS
   register quirk, a DeSmuME-only hang: it didn't work, now it does.
3. **Dependencies: new vs. bumped.** A new library linked into the ROM or a new tool
   → `ADD:` (and it brings THIRD_PARTY_NOTICES/licenses/credits in the same commit).
   Moving the pinned BlocksDS digest, a Docker base image, py-desmume or a pinned
   GitHub Action SHA to a newer version → `UPT:`.
4. **Docs together with code is not `DOCS:`.** `DOCS:` means only docs changed.
   Code plus the matching README/QA/ASSETS update takes the code's prefix.
5. **New docs are still `DOCS:`.** `ADD:`/`DEL:` are for code and dependencies.
   Agent config counts as docs: `.claude/`, `.agents/`, `.codex/` (skills, rules,
   subagents, generated Codex TOML). So do doc-only images and their generator
   (`docs/images/`, `docs/logo/`, `scripts/mklogo.py`).
6. **`.github/workflows/` is code.** It runs and changes results. New workflow →
   `ADD:`, behaviour change → `ADD:`/`FIX:`, tidy-up → `REF:`.
7. **Assets are code here.** They are generated by `tools/`; a new sprite, sound or
   stage is `ADD:`, a broken one fixed is `FIX:`.
8. **Two prefixes fit → split the commit.** "Add a feature and tidy up on the way"
   is two commits.

## 3. Summary line

- English, sentence case, no trailing period, ~50 characters including the prefix.
- Describe the **change**, not the files. Don't repeat the prefix verb
  (`ADD: Add …` → `ADD: …`).
- Name the game when the change is inside one game folder (`FIX: Corvane …`).

```
good:  FIX: Corvane stage 5 white squares from texture bank overflow
bad:   FIX: stage.c changes
bad:   FIX: Fix bug
```

## 4. Body: why

The diff already says what. The body says **why**, especially for code that looks
odd on purpose (DS hardware workarounds, emulator quirks, determinism rules,
licence decisions). Without the reason the next person "cleans it up" and
reintroduces the bug.

```
FIX: Corvane boot hang in EEPROM busy wait

libnds' eepromWaitBusy never returned: the slot-1 bus was not claimed for
AUXSPI and the last byte went out with HOLD still set. Use our own SPI code
that claims the bus, clears HOLD on the final byte and times out every wait.
```

A self-evident change may have the summary only. A body is required when you touch
hardware contracts (`common/cv_ipc.h`, save layout, demo result block, replay
format), licensing files or the pinned toolchain: say what the change is based on.

Keep the trailer lines the tooling asks for (for example `Co-Authored-By:`).

## 5. Branch names

`<prefix in lower case>/<summary-in-kebab-case>`

```
add/release-workflow
fix/corvane-eeprom-hang
ref/vram-plan
del/sky-tile-generator
docs/corvane-gallery
upt/blocksds-1.26
```

## 6. Branch flow and PR titles

```
<prefix>/<summary>  --PR, squash-->  develop  --release PR, merge commit-->  main  --tag-->  release
```

- `develop` and `main` reject direct pushes (rulesets in `.github/rulesets/`).
  Branch off `develop`, push the work branch, open a PR **into `develop`**.
- The PR title is the commit summary (`FIX: Corvane boot hang in EEPROM busy wait`);
  the squash merge uses it as the commit title and the PR body as the message.
  The required check `pr-guard` rejects titles without a prefix.
- **Release** (a new game or a new game version): PR `develop` → `main`, titled
  `Release <game> v<x.y.z>`, merged with a merge commit (squash/rebase are off for
  main; `pr-guard` rejects any head other than `develop`). Then tag the merge
  commit on main: `git tag <game>-v<x.y.z> origin/main && git push origin <game>-v<x.y.z>`.
  The release workflow refuses tags that are not on main.
- PRs need an approval from the code owner @devgyurak (`.github/CODEOWNERS`);
  the maintainer merges their own PRs through the admin bypass.
- Only admins can create tags (tag ruleset). Open, merge or tag only when the user asks.

## 7. Before committing

- [ ] The prefix matches the diff (no `REF:` that changes behaviour).
- [ ] One kind of change per commit.
- [ ] The summary states the change, not file names.
- [ ] Odd-looking code has its **why** in the body or a comment.
- [ ] Game changes meet the definition of done in `AGENTS.md` (warning-free build,
      smoke test, licence audit).
- [ ] Human docs changed together with their `-KO` twins.
- [ ] No ROMs, saves or build output staged (`git status --short | grep -E '\.nds|\.sav|build/|out/'`).
- [ ] Generated files are in sync (`python3 scripts/sync_agents.py --check`,
      `python3 scripts/mklogo.py` leaves no diff).
