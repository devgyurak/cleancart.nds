# cleancart.nds

Original Nintendo DS homebrew games, one per folder under `games/` (`games/corvane/`, `games/hushwell/`, `games/lightenette/`, `games/elevane/`).
Everything that ships in a ROM must be licence-clean: our own code and our own
generated assets, plus clearly noticed third-party runtime libraries.

This file is the single source of truth for both Claude Code and Codex.
`CLAUDE.md` only imports it. Game-specific notes live in `games/<game>/AGENTS.md`.

## Working with the user

- Talk to the user in **Korean**.
- Docs for humans are written in English (`README.md`, `ASSETS.md`, `docs/QA.md`, …) and
  each has a Korean twin next to it named `{name}-KO.md`, linked from the top of both
  (`[한국어](README-KO.md)` / `[English](README.md)`). Change both in the same edit;
  Korean twins link to other Korean twins.
- Code, comments, commit messages, `AGENTS.md`/skills/rules: English only (no `-KO` twin).
- The user tests in **melonDS on macOS** (Korean 2-set input source is the default).
- Don't commit or push unless asked. Never commit ROMs or build output.
- Commit summaries, PR titles and branch names start with one prefix
  (`ADD:` `FIX:` `REF:` `DEL:` `DOCS:` `UPT:`); see skill `commit`.
- Branch flow: work branch → PR into `develop` (squash); a new game or game version
  is released by a PR `develop` → `main` (merge commit) and a `<game>-v<x.y.z>` tag
  on main. Direct pushes to `develop`/`main` are blocked (`.github/rulesets/`,
  applied by `.github/scripts/setup-rulesets.sh`). PRs need an approval from the
  code owner @devgyurak (`.github/CODEOWNERS`); the maintainer merges their own PRs
  through the admin bypass.

## Languages and toolchain

| What | Language / tool |
|---|---|
| Game (ARM9 + own ARM7 core) | C (GCC from BlocksDS, `-O2 -Wall -Wextra`, no C++) |
| Build-time tools (asset generators, stage editor, replay tool) | Python 3, **stdlib only**, deterministic |
| Build | BlocksDS v1.25.0 in Docker, image pinned by digest (`games/<game>/Dockerfile`), driven by `games/<game>/build.sh` → `make` |
| Smoke tests | headless DeSmuME (`tools/emu/`), Docker `--platform linux/amd64` |
| melonDS checks without a screen | headless melonDS 1.1 core (`tools/melonds/mds.sh`, C++ runner in Docker) |
| Manual play / QA | melonDS 1.1 (`~/Applications/melonDS.app`) |

Never install a toolchain on the host for builds; always go through `build.sh`
so builds stay reproducible (two clean builds must give the same SHA-256).

## Licensing rules (non-negotiable)

1. Every source file starts with `SPDX-License-Identifier: Apache-2.0` and
   `SPDX-FileCopyrightText: 2026 Corvane contributors` (use the comment syntax
   of the file; Markdown docs are exempt except skill/rule files are fine either way).
2. Assets (graphics, fonts, models, sounds, music, levels) are generated by
   code in the repo or are CC0. Every asset gets a row in `games/<game>/ASSETS.md`.
   Never paste, trace or sample existing art, fonts or recordings.
   Exception: README screenshots/GIFs captured from our own ROMs live in
   `games/<game>/docs/images/`. They are documentation, not ROM assets (never built into
   the ROM, no ASSETS.md row), and fall under the game's licence. The repository
   logo in `docs/logo/` is generated by `scripts/mklogo.py` (Apache-2.0; edit the
   script, not the SVGs).
3. Originality: genre and mechanics may be borrowed; names, characters, logos,
   level layouts and look of existing games may not. No third-party trademarks
   in game names or code identifiers.
4. Third-party code in the ROM (today: libnds zlib, BlocksDS crts MPL-2.0,
   picolibc BSD-style, libgcc GPL+runtime exception) must be listed in
   `games/<game>/THIRD_PARTY_NOTICES`, its licence text copied into `games/<game>/licenses/`
   (shipped in NitroFS `/licenses/`) and credited in the in-game credits.
   Linking a new library means updating all three in the same change.
5. Use our own ARM7 core: no DSWiFi, lwIP, Mbed TLS, Maxmod or LibXM7.

## Controls and key mapping

| DS button | Game action (corvane) | melonDS keyboard (macOS) |
|---|---|---|
| D-pad | move / menu | arrow keys |
| A | fire (hold = charge) | X |
| B | boost / dodge | Z |
| X | bomb | S |
| Y | (sound test: stop music; elevane: hold for the work layer) | A |
| L / R | rotate camera | Q / W |
| Start | pause | Return |
| Select | developer console; title: choose start stage | Backspace (Delete) |
| Touch | radar lock-on / direct aim | mouse on the bottom screen |
| Lid | auto pause + sleep | C (hotkey) |
| — | melonDS pause / fast-forward / frame step | P / Tab (hold) / N |

QA shortcuts in corvane: title + Select = start-stage select; pause + hold L+R + A = clear stage.
Hushwell maps the same keys to its own actions (walk, examine, run, flashlight, map/recorder,
hush, flare, swap screens); see `games/hushwell/AGENTS.md`. Its QA shortcuts are the same.
`tools/melonds/set_keys.py` writes this mapping (see skill `melonds-mac`).

## Definition of done for game changes

1. `./build.sh` (and `./build.sh demos` if shared code changed) with zero warnings.
2. Smoke test in the headless emulator for the scenes you touched; look at the screenshots.
   DeSmuME has no MPU and skips some DMA modes: check MPU, DMA, cart and save changes
   in headless melonDS (`tools/melonds/mds.sh`) too.
3. Licence audit passes (SPDX headers, ASSETS.md, notices).
4. Every game carries the auto QA mode (skill `nds-qa-mode`): headless melonDS soft with an SD image
   reaches the credits with `RESULT PASS`, the log passes `tools/qa/parse_log.py`, DeSmuME reaches
   the end too, two runs give identical checkpoint hashes, `tools/qa/lint.py` passes, and with QA off
   nothing changed. Games with `expected.json` + `judge.py` also run it on all four renderers and
   match the known profiles.
5. Report honestly what was verified where (DeSmuME ≠ melonDS ≠ hardware).
